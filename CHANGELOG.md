## [Unreleased]
### Added
- [031] Added manual end-of-day price upload to the admin **Dailies** page, reaching `POST /imports/eod` — an admin-only endpoint the web app had never called, alongside the whole `services/importer` module and the `Dropzone`/`FileInput` components, none of which had a consumer. Selecting a listing enables **Upload prices**, which takes a Brand New Day CSV (`date`, `nav`, `ask`, `bid`, `dividend`; dates `dd/mm/yyyy`) and states that format up front rather than letting a rejected upload teach it. Only listings on a manual provider are accepted; the API is left as the authority on which those are and its 422 is reported in place, naming the provider the listing actually prices from, because the canonical source values (`market_stack`) and the fixture values (`marketstack`) differ and a client-side guess would be wrong. Processing is asynchronous with no status endpoint and no websocket event — EOD imports carry no account scope — so the page re-reads the listing's prices for a short window and reports how many rows landed, or says it is still processing rather than claiming an outcome it cannot observe.
- [030] Enforced authentication across the API. Every route is registered through a default-deny tier (`protected`), with `public` reserved for health, Swagger and the sign-in endpoints and `adminOnly` for account administration, market-data curation, provider credentials and EOD imports — so the `admin` flag is now enforced (403) rather than merely hiding screens. The account for every request comes from the session instead of a client-supplied `account_id`, which is gone from all request DTOs, query strings and multipart forms across cashflow, portfolio, assets and imports. Added a sign-in allowlist (`auth.allowed_emails`), checked on every login so removing an address locks it out; an Origin check on state-changing requests; a periodic expired-session sweep; and config that refuses to boot outside development with authentication off or the allowlist empty.
- [030] Added the web sign-in flow: a `/login` page rendering one button per configured provider with readable messages for each failure reason, a session-backed `accountStore` sourced from `GET /auth/me` (replacing the `GET /accounts` bootstrap), `credentials: 'include'` on every request, a central 401 handler that returns to sign-in when a session lapses, a root-layout guard, and a working **Sign out** in the account menu that labels itself with the signed-in address.
- [030] Added OpenID Connect sign-in (Google first, any compliant provider by configuration). The API runs the Authorization Code + PKCE flow itself, verifies the ID token once and discards it, then issues its own opaque, revocable session cookie (`HttpOnly`, `SameSite=Lax`); no provider token is ever stored. New endpoints `GET /auth/providers`, `GET /auth/{provider}/login`, `GET /auth/{provider}/callback`, `GET /auth/me` and `POST /auth/logout`. Per person the application keeps an id and an email, plus one pseudonymous `(issuer, subject)` row per provider, so a second provider linked to the same **verified** email resolves to the same account; linking on an unverified email is refused. New migrations in both dialects add `accounts.email`, `identities` and `sessions`. Sign-in is off by default (`auth.enabled`) and nothing is enforced yet — endpoints still accept a client-supplied `account_id`.
- [020] Integrated Cashflow, Portfolio and Assets creation actions into ruled ledger headers as labeled plus buttons, replacing floating controls.
- [028] Added an admin **Credentials** page and provider-credential API (`GET /marketdata/providers`, `PATCH /marketdata/providers/{id}/credentials`, `POST /marketdata/providers/{id}/credentials/reveal`) for managing external API keys. Listings return only a masked hint (`****9876`) and never the stored key; revealing one is a separate POST that is logged. Manual providers are listed but reject credential updates.
- [029] Added an `admin` flag to accounts (new migration in both dialects, exposed on `GET /accounts`, set for the bootstrapped account). Admin screens are omitted from the navigation for non-admin accounts and show an unavailable notice on a direct link. The API does not enforce the flag — it hides screens, it does not protect them.
- [006] Added provider-catalogue listing search: `GET /marketdata/listings/search` now takes a `scope` (`tracked` default, `catalogue`, `all`) and returns tracked listings alongside a locally cached copy of the provider's ticker catalogue, each row reporting `tracked`, `has_eod` and whether it can be adopted. New `POST /marketdata/catalogue/search` runs one metered provider request and merges the results into the cache, `POST /marketdata/catalogue/sync` starts a bounded background seed run (capped at 100 pages), and `GET /marketdata/catalogue/status` reports cached entries and the last run for a staleness warning. Backed by new `provider_listings` and `catalogue_syncs` tables and a `SearchTickers` implementation on the MarketStack client.
- [005] Added listing edit and delete to the admin listings page, with a `DELETE /marketdata/listing/{listing_id}` endpoint the API did not have. Editing reaches the existing `PATCH /marketdata/listing`, which had no caller in the web app: it patches instrument metadata only — symbol, name and source identify the instrument at the provider and are shown rather than offered — and sends just the fields that changed, so reverting an edit disables Save rather than submitting an empty patch the endpoint would reject. Deleting is refused with 409 while a portfolio references the listing: every listing foreign key either cascades (position snapshots, end-of-day prices, upload records) or nulls (open positions), so an unguarded delete would silently destroy an account's valuation history and orphan its holdings. Price history is not counted as usage, so a listing nothing holds deletes cleanly. Covered by integration tests for all three outcomes against a migrated database.
- [006] Added **Resync catalogue** to the provider-catalogue drawer, so the staleness warning it already showed has an action that resolves it. It starts the bounded seed run behind `POST /marketdata/catalogue/sync`, which had no caller in the web app. The run is detached from the request that starts it, so the drawer polls `catalogue/status` while one is in flight and shows live progress (pages fetched, entries cached) in place of the staleness line, then announces the outcome. The button names its cost — one provider request per page, 20 by default — matching how the metered search is labelled. Reopening the drawer mid-run picks the run back up, and a 409 from a run started elsewhere is followed rather than reported as a failure.
- [006] Added a **Browse catalogue** drawer to the admin listings page with multi-select bulk adoption, per-row outcomes so one duplicate does not sink a batch, an explicit metered "Search provider" action, a truncation notice when the provider matched more than it returned, and a catalogue staleness line. ### Fixed
- [024] Fixed `PUT /assets/{asset_id}/adjust` storing every adjustment with the zero time. Validation parsed the effective date with Go's reference layout and rejected bad input correctly, but the handler then re-parsed it with the literal `"2026-01-02"` — a date, not a layout — and discarded the error, so the parse never succeeded and the date the caller sent was thrown away. The file now uses `time.DateOnly`, which cannot be mistyped into an invalid layout. The same literal appears at 19 other call sites that were not touched.
- [024] Fixed `DELETE /assets/classes/{class_id}` continuing after it had already answered. Both the decode-error and validation branches wrote a 400 and fell through to delete the class anyway, and the 500 branch fell through to write a second header. Its not-found check also called `errors.Is` with the arguments reversed, so a missing or foreign class answered 500 instead of 404.
- [024] Fixed `PATCH /assets/classes` skipping validation entirely: `UpdateClassRequest.isValid` had no caller, so a class name of any length reached the command. It is now applied, and a missing or foreign class answers 404 rather than 500.
- [024] Fixed two silently dropped errors in the assets write path. Creating an asset ignored the result of its opening-balance mutation, so a failure left an asset whose worth nothing accounted for; updating an asset's worth ignored the class-total aggregation error and wrote the mutation against a zero total. Both now fail the surrounding transaction.
- [006] Fixed the admin dailies table surviving a cleared search. `ListingSearchSelect` reset its own text and selection but the page held the chosen listing in its own state behind a one-way `value`, so clearing the box left a full table of prices on screen with nothing naming the listing they belonged to. The component gained an `onClear` callback and the page drops its selection on it. Typing deliberately does not fire it -- that invalidates the selection but keeps the last result visible until a new one is chosen.
- [006] Fixed the admin dailies table being able to show one listing's prices under another's name. A listing's history is one unbounded request and nothing ordered them, so picking a second listing while the first was still loading could see the responses resolve out of order, and clearing the search mid-load left the abandoned response to flip the spinner off. Loads now carry a request id in the same shape `ListingSearchSelect` already uses for its searches: every write is gated on still being the newest request, and clearing bumps the id so a response arriving after the table is emptied has nothing to land in.
- [006] Fixed the provider-catalogue drawer keeping a stale truncation notice. "The provider matched N instruments and returned the top 100" describes one metered response, but only `askProvider` ever set it, so a following local search, a page change or a reopen left it asserting a count for results no longer on screen. It is now dropped whenever the rows are replaced by anything other than a provider search.
- [020] Fixed EB Garamond rendering every heading at regular weight. Its `@font-face` declared `font-weight: 400 700` while only a static regular ships, so the browser treated that one face as covering the whole range and suppressed synthetic bolding — `font-semibold` on a heading resolved back to 400 and rendered identically. Measured at 36px, ink coverage is now 49% higher at weight 600 than at 400 where it was previously identical, restoring the weight step on page titles and the sign-in heading.
- [020] Fixed dialog and drawer titles reading no larger than their own body copy. Both shells hand-rolled a `<h2 class="text-xl">`, bypassing the `Heading` atom, so the title carried no weight and — EB Garamond having a much smaller x-height than Noto Sans — its lowercase letters measured exactly the body text's 8px, leaving a form label at `font-medium` visually heavier than the title above it. Both now render `Heading level="h2" size="lg"` (24px, semibold), taking the title's x-height to 11px against the body's 8px. Applies to every dialog and drawer: add listing, provider credentials, new asset class, new transaction, and the asset-class and provider-catalogue drawers.
- [020] Fixed search fields showing two clear buttons. `SearchInput` and `ListingSearchSelect` both set `type="search"` and draw their own clear control, while Chromium also paints its native `::-webkit-search-cancel-button` inside the field — so a non-empty search box offered two X's a few pixels apart. The native affordance is now suppressed on both, leaving the component's own button as the only one.
- [013] Fixed portfolio rebuilds ignoring share splits. Quantity was accumulated from raw broker transactions while prices from the split date onward are post-split, so every snapshot after a split understated the position (a 4-for-1 reported a quarter of the real holding), selling the full post-split quantity was clamped to the pre-split share count and left a phantom position open, and realized profit was booked against the wrong number of shares. The provider already reports `split_factor` on every end-of-day row, so it is now stored alongside the prices it applies to (new migration in both dialects) and replayed during rebuild as a synthetic event in the same chronological stream as the trades — ordered before same-day trades, which are already quoted post-split. Manually imported end-of-day files and pre-existing rows default to a neutral factor and are unaffected.
- [006] Fixed provider-catalogue search returning 500. The MarketStack client called `/v2/tickers`, which is the v1 endpoint name and answers 404 `Route not found` on v2 — the catalogue endpoint there is `/v2/tickerslist`. The response shape was already correct, so only the path changed; pinned by a test asserting the requested path and that a provider error is not billed as a request.
- [030] Closed cross-account access in cashflow, which had no account scoping at all: transaction listing, monthly analytics and tag distribution summed across every account, and tagging or ignoring by id or filter could reach another account's rows. `TransactionListQuery`, `AnalyticsFilter` and `TransactionFilters` now carry the account and every store query is predicated on it. Also scoped `assets.UpdateClass`, which unlike `DeleteClass` never checked class ownership, and the realtime WebSocket, which trusted the account id in its path rather than the session.
- [024] Fixed `GET /assets/snapshots` date handling: it used the literal layout `"2026-01-02"` instead of Go's reference layout `"2006-01-02"` when parsing `from`/`to` and formatting the snapshot date (so date-range filtering was wrong), and added the missing early return when query decoding fails.
